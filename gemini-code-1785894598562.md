# Project Prompt: Velocity WhatsApp Registration Bot & Admin Management System

## 1. Context & Objective
Saya memiliki komunitas bahasa Inggris dengan grup WhatsApp bernama **"Velocity"**. 
Saya ingin membangun sistem otomatisasi berbasis WhatsApp Bot dan Web Admin Dashboard. 
Tujuan utamanya adalah melakukan pendataan/re-registrasi ulang terhadap seluruh anggota grup:
1. Menanyakan apakah anggota masih ingin melanjutkan pelatihan ekskul Bahasa Inggris.
2. Jika **Ya**, mengumpulkan data diri (Nama, Kelas, Alasan/Kemauan belajar Bahasa Inggris, dan Hobi).
3. Jika **Tidak**, mencatat nomor tersebut ke dalam daftar keluarkan (kick list) untuk admin.
4. Jika **Belum Membalas**, mengirimkan pesan pengingat secara berkala sampai dijawab.
5. Menampilkan seluruh data dan status pendaftaran pada halaman Dashboard Admin berbasis web.
6. **WhatsApp Session Persistence**: Sesi login WhatsApp harus tersimpan secara permanen (di Database atau Persistent Storage). Bot TIDAK BOHLEH meminta scan QR ulang setiap kali ada redeploy server, restart service, atau update kode. Scan QR cukup dilakukan 1x di awal saja.

## 3. Core Features & System Workflow

### A. Core Bot State Machine & Flow
Setiap nomor yang terdaftar di database akan memiliki state/status percakapan:

1. **Inisiation & Konfirmasi (Pertanyaan Pertama)**:
   - Bot mengirim pesan: *"Halo! Apakah kamu masih ingin melanjutkan pelatihan ekskul Bahasa Inggris di komunitas Velocity? (Balas: YA / TIDAK)"*
   - Status DB: `WAITING_CONFIRMATION`

2. **Percabangan Jawaban**:
   - **Jika Jawab "TIDAK"**:
     - Bot membalas: *"Baik, terima kasih atas konfirmasinya. Data kamu telah dicatat."*
     - Status DB: `OPTED_OUT` (Kirim ke daftar Kick List Admin).
     - Hentikan pesan pengingat.
   - **Jika Jawab "YA"**:
     - Bot melanjutkan ke pertanyaan berikutnya secara bertahap:
       1. *"Siapa nama lengkap kamu?"* -> Status: `WAITING_NAME`
       2. *"Kamu dari kelas berapa?"* -> Status: `WAITING_CLASS`
       3. *"Apa motivasi/kemauan kamu untuk mempelajari bahasa Inggris?"* -> Status: `WAITING_MOTIVATION`
       4. *"Apa hobi kamu?"* -> Status: `WAITING_HOBBY`
     - Setelah semua terisi:
       - Bot membalas: *"Terima kasih! Data pendaftaran kamu berhasil disimpan."*
       - Status DB: `COMPLETED`
   - **Jika Tidak Membalas / Mengabaikan**:
     - Cron Job/Scheduler akan mengecek nomor dengan status `WAITING_CONFIRMATION` secara otomatis.
     - Bot mengirimkan ulang pesan pertanyaan pertama sampai ada jawaban (`YA` atau `TIDAK`).

### B. WhatsApp Session Persistence (Anti Scan Ulang saat Deploy)
- Sesi autentikasi WhatsApp (`auth_info` / credentials Baileys) **harus disimpan secara otomatis ke dalam PostgreSQL Database (via Prisma)** atau menggunakan adapter session database.
- Saat aplikasi di-redeploy atau server di-restart:
  1. Service bot akan membaca kredensial sesi dari database.
  2. Bot langsung melakukan otomatis reconnect tanpa memicu *logout* atau regenerasi QR code.
  3. QR Code scanner pada Dashboard Admin hanya akan aktif jika kredensial di database kosong, terhapus, atau ter-logout secara eksplisit oleh pengguna dari HP.

### C. Exception & Exclusion Handling
- Admin bisa memasukkan list nomor telepon yang **dikecualikan (Exclusion List)** agar bot TIDAK mengirimkan pesan ke nomor-nomor tersebut (contoh: Nomor Pembina, Ketua, atau Admin).

### D. Web Landing Page & Admin Dashboard
1. **Public Landing Page (`/`)**:
   - Tampilan sementara sederhana (Hero section singkat dengan informasi ekskul Velocity & status pendaftaran via WhatsApp). 
   - *Fokus utama pengembangan AI diutamakan pada fungsi Bot & Dashboard Admin terlebih dahulu.*
2. **Admin Dashboard (`/admin`)**:
   - **Protected Route**: Otentikasi sederhana (NextAuth / Supabase Auth).
   - **Tabel Data Peserta (`/admin/participants`)**:
     - Menampilkan list semua peserta, status (`COMPLETED`, `WAITING_CONFIRMATION`, `OPTED_OUT`, `EXCLUDED`).
     - Detail jawaban: Nama, Kelas, Motivasi, Hobi, No HP.
     - Filter berdasarkan status & pencarian nama/nomor HP.
     - Fitur **Export Data** (CSV / Excel).
   - **Tabel Kick List (`/admin/kick-list`)**:
     - Menampilkan daftar nomor yang memilih `TIDAK` atau diprioritaskan untuk dikeluarkan dari grup Velocity.
     - Tombol untuk menandai apakah sudah di-kick secara manual.
   - **Exclusion List Management (`/admin/exclusions`)**:
     - Form untuk menambah/menghapus nomor yang dikecualikan dari broadcast bot.
   - **Bot Control & QR Code Scanner (`/admin/bot`)**:
     - Menampilkan status koneksi WhatsApp Bot (`Connected`, `Connecting`, `Disconnected`).
     - Menampilkan QR Code HANYA jika bot belum terhubung / sesi baru.
     - Tombol **"Logout Session"** jika admin ingin mengganti nomor bot WhatsApp secara manual.

## 4. Database Schema Proposal (Prisma Schema)

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

enum RegistrationStatus {
  NOT_STARTED
  WAITING_CONFIRMATION
  WAITING_NAME
  WAITING_CLASS
  WAITING_MOTIVATION
  WAITING_HOBBY
  COMPLETED
  OPTED_OUT
}

model Participant {
  id              String             @id @default(uuid())
  phoneNumber     String             @unique // Format International: 628xxx
  name            String?
  studentClass    String?            // Kelas
  motivation      String?            // Kemauan/Alasan belajar
  hobby           String?
  status          RegistrationStatus @default(NOT_STARTED)
  isExcluded      Boolean            @default(false) // Jika true, bot tidak kirim pesan
  isKickedFromGrp Boolean            @default(false) // Penanda admin untuk kick list
  lastSentAt      DateTime?
  createdAt       DateTime           @default(now())
  updatedAt       DateTime           @updatedAt
}

// Model khusus untuk menyimpan Session Auth WhatsApp (Anti Scan Ulang saat Redeploy)
model BaileysAuth {
  id        String   @id @default(uuid())
  key       String   @unique
  value     Json
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

model SystemSetting {
  key   String @id
  value String
}
